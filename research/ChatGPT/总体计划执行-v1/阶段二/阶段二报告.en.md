# Stage 2: shared execution foundation

[English](阶段二报告.en.md) | [简体中文](阶段二报告.md)

I completed the common research executor on 2026-10-29, then recorded correctness repairs in a separate review. This report's measured timings refer to its original code hash; they must not be relabeled as post-repair performance.

The Python/SQLite reference gives every backend the same request identity, pinned snapshot, scope and scoring contract. Requests include a query vector/text, K, source/time filters, target quality, counter limits and a deadline. Actions prepare candidates, score, select, fetch sources and commit. State retains phase, cursor, candidates, scores, dependencies and cumulative consumption so a funded continuation can resume the same request.

Backends are full float64 canonical inner product, USearch cosine candidate search with canonical reranking, and Chinese character/bigram lexical retrieval combined by RRF. ANN uses 50 candidates with ef128 in the fixed baseline. Native float32 internal distances and float64 reranking remain different operations. An ordinary exact-request LRU is shared rather than credited as a new architecture mechanism.

SQLite stores immutable document histories and publication revisions. Requests read a pinned materialized snapshot. Appends, modifications, deletion and visibility changes create later state; historical pinned results are distinguished from latest-snapshot requests. Current source verification concerns materialized text, not independent access to the original filesystem. Repaired code adds persistent content hashes and stronger store ownership checks; see the repair report for those changes.

The ledger accounts for model/network, vector loading, scoring, metadata, cache use, source fetches, state commits, initialization and maintenance where implemented. Atomic admission prevents known multi-resource batches from partially spending allowances. Fallback and resume share the parent budget. Some native internals are observed only after calls; unsupported hard limits are rejected. Deadline checking does not establish instantaneous I/O cancellation.

The real frozen experiment has 1,213 chunks at revision 1216, dimension 1024. Run-002 records 474 engineering requests, including a 432-request main comparison. Historical warm means were approximately full 4.217 ms, ANN 3.156 ms and hybrid 6.568 ms. These numbers describe the fixed small diagnostic and pre-repair code, not universal search speeds, formal semantic quality or post-repair timing. Loading, setup, source and commit costs are separately reported in the summary.

Twelve fictitious correctness checks cover tie order, shared cache accounting, ANN/hybrid scope, budget truncation and persistence, request identity, update/delete/visibility behavior, invalid inputs, unsupported native limits, empty ranges and reopening. Later counterexamples led to seven repaired predicates and four additional boundaries. No production update concurrency, power-loss recovery, semantic-label acceptance or architecture novelty follows from those checks.

The stage establishes a comparable engineering foundation. It does not prove the shared-state hypothesis. Old stores and results stay intact; the repaired schema rejects unsupported old histories rather than silently changing them. Stage progression remains a separate review decision.
