## 接口用法

```python
from framework import Store, Engine, Request, Scope, SCORE, HYBRID_SCORE, Ledger

# db_path必须是自己的隔离实验SQLite，不要指向原知识库或阶段一冻结库。
store = Store(db_path, dim=1024, model=model_namespace)
snapshot = store.snapshot()  # 已导入的最新修订
engine = Engine(store, snapshot)
request = Request(bge_query_vector, backend='ann', k=10,
                  scope=Scope(source_prefix='某来源/'), score_contract=SCORE)
result = engine.run(request)
```

完整评分backend='full'；中文混合backend='hybrid'时需传查询text及HYBRID_SCORE。K超过配置的近似候选池会被拒绝；少于K个可见资料时可以返回更少项，不把空结果等同于已证明无答案。

HYBRID_SCORE是默认50候选的常量；自定义candidates时，请使用engine.hybrid_score传入契约，避免把实际3/3或4/4池错误标成50/50。

Engine是绑定快照的执行器。普通新请求不指定snapshot时，只允许它绑定的版本仍为最新；更新后应创建绑定新Snapshot的执行器。明确要读取保留旧版本时，传snapshot=旧identity。读取历史快照是显式时间语义，不得包装成最新查询结果。历史行目前不做回收；历史资源增长属于后续可靠性/维护研究。

## 预算与接续

```python
request = Request(bge_query_vector, backend='full', use_cache=False,
                  limits={'canonical_scores':200})
pending = engine.run(request)
# pending.kind == 'pending'，已计200项；允许增加预算，不允许抹掉已消费量。
request.limits = {'canonical_scores':1213}
result = engine.run(request, pending.state)
```

需要持久化时：ledger=Ledger(consumed=pending.state.consumed)，store.save(pending.state, ledger)；恢复用store.restore(signature)，再以相同请求/评分/快照运行。保存操作也收费，示例不承诺给定上限内有免费checkpoint。明确的预算计数含规范计分、向量逻辑读取、元数据、来源、部分构建/调用数和提交数；不支持的硬预算会拒绝。

save拒绝低于state既有消耗的Ledger，不能通过另建空账抹掉历史工作。prepare_step及已完成范围/ANN结果一同保存，恢复不重复已完成动作。consumed是跨接续累计计数，seconds是当前一次调用的时间；多个调用的时长可相加，累计计数不能再逐次相加。

ANN内部距离数与visited数是实际返回后的观测，不能用作可中途强制的硬上限。native ANN与FTS内部调用不能承诺立即取消；deadline_ms目前在规范计分批次间软检查。没有严格硬实时保证。

结果状态的含义：

- approximate：ANN/混合为近似；完整评分附exhaustive_under_canonical_f64范围，不是实数严格证书。
- pending：已完成工作与资源保留，可在同契约下增加预算继续。
- rejected：输入、快照、评分/质量或预算能力不支持等原因；必须查看reason。
- probabilistic/certified：仅预留类型，本阶段不发出。

同一保存状态改变查询、模型/评分、过滤、后端或快照不能接续。崩溃/断电、跨进程在途任务恢复没有在本阶段验证。

## 更新与来源

Store.mutate(operation_id, operations)支持put/delete，put携带完整向量、文本、path、visible、updated和provenance。同一ID同摘要幂等返回原修订，同ID不同请求拒绝；一批内重复文档ID拒绝。只能在实验副本中使用。真实内容改写后，应由已指定BGE-M3产生匹配正文的新向量；本轮夹具复用旧向量仅验证机械传播。

来源从绑定快照返回文本、版本、路径、原分块定位及哈希。本轮不逐请求访问原库，故不能声称检测到了原库在实验副本之外的实时变化。日期过滤使用暂定元数据updated，缺值在请求时间过滤时排除；未验证该字段代表叙述时间还是文档更新时间。

content_sha现于摄入/修改时保存，source_verification.snapshot_content标明内部正文摘要比对，source_verification.original_file固定false，计数名为materialized_text_checks。保留的file_sha是来源元数据，不代表已实时比对原文件。库命名空间含规范路径，快照另有内容摘要；复制/移动库后不自动接受原库checkpoint，当前没有迁移接续协议。

## 计时和共享基线

所有后端同样可使用驻留向量、普通结果LRU及相同更新/来源接口。结果缓存避免重新搜索，但本参考路径仍读取来源并提交执行记录；缓存命中约3ms的结果受这个策略影响。

资源seconds.prepare包含ANN/词法子调用，不能与这些子计时重复求和；canonical_score、rank、source_fetch、state_commit为其他主要阶段，总时间还含验证/序列化。物理I/O、WAL字节、ANN内部读取字节、FTS posting访问、进程RSS未知；逻辑字节计数不代替这些指标。

本框架没有实现阶段三的语义候选复用/预取，也没有实现阶段四认证。不要把枚举或接口存在当作相应机制完成。
