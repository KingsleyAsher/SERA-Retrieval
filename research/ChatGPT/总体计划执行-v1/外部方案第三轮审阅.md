## 3. DeepSeek：仍阻塞机制评估的四项问题

### D3-1 精确签名使研究对象退回重复查询

第 62 行明确“精确签名哈希；相似签名首版不启用”。若查询签名覆盖完整查询向量/文本与评分条件，改写查询不能命中旧查询条目。此前 24/32 改写覆盖观察因此不能用来支持这个首版的命中率或补齐收益。

若只做相同查询、相同快照、相同过滤和评分，则普通结果缓存已经能复用此前返回结果，维持此前的近似质量；反复重评分 200 个种子并检查邻边需要额外理由。旧结果是 ANN 近似结果时，邻域有可能改善它，但这属于重复查询上的质量增强，应给基线相同的一次性增强机会、缓存更好结果并完整计费，不能把普通缓存收益算作新机制收益。

**采纳决定：**精确结果缓存属于阶段二/三的公共强基线。CSER 若要研究改写复用，必须单独定义相似条目检索，例如仅在既有查询缓存中按当前查询相似度取固定数量旧条目，明确代价、容量及门控。此检索不是全库真正热启动，也不需要为此立刻训练模型。该模块的缺口不阻塞其他阶段工作。

缓存键还需覆盖嵌入模型/版本、查询预处理、评分契约、过滤/可见范围、快照和结果 K 等依赖；若用哈希，需要身份核验规则，不能把哈希碰撞当语义命中。

### D3-2 返回门控可能反而禁止邻域补齐有效

第 92 行 `seeds_cover_R_local(R_local, legal)` 未定义，文字称“已重评分覆盖条件”。

若它表示“最终本地前 K 都来自原种子”，则新邻居一旦进入前 K 就必须委托。最小例：K=2，种子距离为 a:2、b:3，邻居 c:1，正确本地结果为 c、a；要求结果均属于种子会拒绝这次有效补齐。若它表示“所有返回项已在本查询下评分”，则它只是执行完成标记，并不证明库外没有更好项。不能把两者混为证书。

**采纳决定：**要求作者选定精确定义，允许补齐项进入结果；首版输出显式标为近似或经验估计。风险未校准时不得用含糊门控宣称已确认质量。全局委托也需以相同快照/过滤重排去重，不能因“全局优先覆盖”破坏统一排序。

第 38、80 行现在展开全部 C 个合法种子的邻居，不再是上一轮仅展开种子 topK 的策略。C=200、M=32 时最多检查 6400 条邻边（去重后计分可能更少），在 1213 片段小库上候选甚至可能覆盖全库。应显式预算展开种子数、边校验和唯一计分项，记录退化；这是待评估配置变化，不直接判定机制无效。

### D3-3 独立校准仍缺有限样本和选择策略

第 122 行“在校准集验证失败率≤δ”不能仅靠观察比例。需要预先固定策略/阈值，再对被该策略接受的独立样本给出带置信水平的失败率上界；若在同一校准集挑阈值，要控制阈值选择造成的偏差。问题族内变体不能当成独立查询来虚增证据。

示例仅为说明样本限制：若有 n 个独立同分布的本地返回样本，策略已固定，观察到 0 次失败，则单侧 95% 精确二项上界为 `1−0.05^(1/n)`。n=24 时约 11.73%；要把该上界压到 5% 以下至少需要 59 个这样的零失败样本。这不是对当前 24 个测试族的自动保证，也不是本轮变更数据集计划。

第 124 行“必须覆盖所有风险档才能有任何组保证”过强。对固定接受策略的条件组，可以用该组内有代表性的独立样本估计其风险；未接受组没有标签并不会逻辑上否定该条件组结论。为训练、选择阈值、监控漂移而覆盖多风险档仍很有用。应区分训练覆盖、策略选择和最终验证。

Rt 与“遗漏任一真 topK”的 Y 定义也要对应。K=10、Rt=.95 时，离散召回步长为 .1，达标确实要求全十正确；一般 Rt/K 不能默认等价。

### D3-4 消融与退出规则有错误归因

- 第 147 行“G4 优于 G3 但不优于 G2，因此收益来自种子而非邻域”不能推出。G4/G3 若其他因素受控，恰是在比较邻域的贡献；输给 G2 仅说明该联合路线未赢这个更强基线。
- G3 可能需要单独校准自己的策略，不能拿 G4 的阈值直接比较后声称机制归因。质量/成本应比较匹配质量点或预先规定的性能前沿。
- 本地返回组和委托组难度不同，两组召回有差异不能单独证明机制失效。应在相同查询上对照精确参考和基线，并检验各组是否满足自己的目标。
- AUROC≈.5 不自动意味着不能用：若风险恒低且符合目标，常数策略也可能有用。首轮先比较规则与常数策略，无需为了机制名称训练模型。
- 缺少相同查询结果缓存这个最强相关对照；G1 未命中行为、各路径内存/邻域构建预算也需明确。未使用邻域的基线无需强迫构建无用邻域，但应有同等资源上限和可用优化机会。
- 第 143 行的 P99 先降为原始延迟分布及 P50/P95；当前小样本不支持稳定 P99 结论。

## 4. WorkBuddy：可采纳参考核心，保留四项实现约束

### W3-1 精确解码与固定尺度整数路径可采纳

位模式解码对有限正规数、次正规数、±0 的处理正确；统一距离单位 2^-298，可直接比较整数。最大值分析和 566/567/572 位幅值界也与简查一致。首版可使用 Python 任意精度整数，避免过早引入固定宽度和平台特定快路。

128 位自适应路径的“指数”仍未定义一致：前文 exp 指原始 8 位指数域，后文却用 `2^(-min_exp)` 作为坐标整数尺度。以 FP32 1.0 为例，原始 exp=127，乘 2^-127 不会得到整数。

可行写法是沿用固定尺度解码：对非零坐标定义移位 h=max(exp−1,0)，取所有参与比较坐标的共同 h_min，将解码整数统一右移 h_min（其整除性需说明）；若 h_max−h_min≤33 且 D≤1024，幅值估计可支持有符号128位。零应跳过指数范围统计，全零单独处理。这只是未来可选规格，本轮不实现，也不阻塞大整数参考路径。

### W3-2 实数残差界正确，机器认证协议还未完整

恒等旋转下，截断后平方的残差下界与候选包含条件成立，避免了非恒等坐标问题。但“FP32 范数向上舍入/加1 ulp”不自动覆盖此前求残差、平方、求和、开方已发生的误差；最后一次向上转换不能修复更早的低估。

需要完整的保守链：以已声明的重构坐标为准，对真实残差范数求上界 r_U，对查询到重构点的平方距离求下界 a_L，构造向下包围的 `max(sqrt_down(a_L)−r_U,0)^2`；与第 K 边界的保守上界 T_U 比较，只有严格 `LB > T_U` 才安全排除。边界未分离时走精确比较或 Pending；不能以审计字段写了 identity/dyadic 就证明执行正确。包含池条件还要明确对哪个方向的区间做比较，防止舍入造成假阴性。

因此采纳数学参考公式，机器证书仍需阶段四规定的验证器与边界反例后才能发出。无需为此恢复非恒等 OPQ 推导。

### W3-3 COMMIT 不自动等于断电持久化

第 259 行把 SQLite COMMIT 直接解释成 WAL 已 fsync，需要附配置与故障范围。在 WAL+synchronous=NORMAL 下，事务提交可能在系统崩溃/断电后丢失；应用进程崩溃与系统故障不能混写。WAL+FULL 才提供额外的每事务同步，仍依赖底层文件系统/设备兑现同步语义。[SQLite 官方 synchronous 文档](https://www.sqlite.org/pragma.html#pragma_synchronous)

SQLite 提交也不会替应用同步外置 segment。应先完成不可变文件写入、校验与所需持久化，再提交发布记录；恢复只依据已提交目录校验引用文件。操作 ID、请求摘要、操作结果和发布变更应在同一事务提交；重复 ID 携带不同请求应拒绝，不能一律“返回成功”。

这属于阶段二骨架及后续可靠性规格，当前没有开展断电或故障实验。

### W3-4 资源预留与状态需按总体接口收敛

串行已知批次的计数归纳成立。但第 313–314 行仅在完成后更新 actual，不等于对并发/异步在途工作做预留。统一规则应为原子检查 `consumed + reserved + next ≤ budget`，先增加 reserved，再发起工作；结束/取消时按真实计费转换，所有重排、精确兜底、I/O 和回退共用账本。

“超一个实际批次时长”不是事前可承诺的有限时限。只有明确执行/取消边界时才可作事后描述；不得包装为硬实时保证。

第 362 行预算不足直接 REJECTED，与本项目已锁定的“预算耗尽保留接续并 Pending”不一致。若状态可保存，应 Pending；仅在不支持/不能继续或调用契约要求拒绝时 Rejected，并明确原因。

## 6. 融合决定与停止点

1. 采纳 WorkBuddy 的固定尺度大整数参考、精确平局规则、恒等残差数学界、提交记录权威及独立计费方向；附上述机器/恢复/接续条件。非恒等 OPQ 继续搁置。
2. 采纳 DeepSeek 对“外部补齐”、同快照和经验风险的边界澄清；其新增精确签名路线放进普通缓存对照，改写复用和未定义门控仍是该候选模块的修订项。
3. 共享执行骨架先容纳普通结果缓存、候选复用、全局搜索与显式质量状态；不为尚未闭合的某个模块强行确定默认路径。这与原阶段顺序一致，不构成主线变更。
4. 不需要两方继续扩展新架构层。若继续推理，仅回答随附有限问题；已经修对的部分冻结，避免无限改写文档代替实验。
5. 本轮没有新增速度、负载、语义质量或稳定性提升数字。当前实质进展是认证参考核心收敛、外部补齐的适用性缺口被定位。

按用户阶段约定，本部分完成后停下报告。阶段一质量初标仍待用户抽查，阶段二未开始，不自动开启实验、训练或消息发送。
