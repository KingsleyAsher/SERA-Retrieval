# Implementation notes for stage 3.2

[English](实现说明.en.md) | [简体中文](实现说明.md)

I isolated this executor from stage 3.1 so its earlier results remain reproducible under the matching code. `execution_engine.py` derives the candidate executor, `layouts.py` provides JSON/compact candidate banks and the controllable IVF reference, `run_experiment.py` executes the fixed matrix, and `finalize_report.py` only aggregates saved records. `measure_startup.py` measures a separate import probe.

Compact matching still reads/copies the entire bank's logical payload. Both layouts select the same old entry and seed IDs. IVF owns a snapshot-bound index; warm search rescored seeds before modifying list priority and skips duplicate current-query scores. Fixed scan budgets include seeds.

Enumeration progress, pending positions and canonical scoring progress are different facts. `opened` means a posting list was opened, not completed. Existing fields retain list/member and score cursors; stronger unfinished-region coverage requirements belong to the next protocol. This implementation has no upper-bound pruning or learned stop rule.

The ten fictitious checks and code hashes are recorded beside the scripts. Replay inputs stay private; missing cached embeddings fail rather than call an API. Common and per-arm setup/fill costs are separate, and native ANN subtime is not added twice inside prepare time. No prior executor, raw run or production path is overwritten.
