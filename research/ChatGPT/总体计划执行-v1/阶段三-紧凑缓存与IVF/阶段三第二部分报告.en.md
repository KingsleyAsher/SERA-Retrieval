# Stage 3.2: compact candidate storage and controllable IVF

[English](阶段三第二部分报告.en.md) | [简体中文](阶段三第二部分报告.md)

I completed this part on 2026-10-29. Compact storage produces a repeatable engineering gain. A controllable IVF backend now uses rescored seeds to change its actual partition frontier, but the frozen matrix does not demonstrate stable net superiority over mature ANN or the strongest cold-IVF configurations.

The same private snapshot contains 1,213 chunks at revision 1216 with BGE-M3 dense1024. No embedding API, expert training, corpus expansion or production replacement occurs. The workload remains 16 development families, 48 unique texts and 32 rewrites. Semantic labels are unreviewed.

There are 44 configurations: ANN/full references; JSON/compact seed and merge routes at C=10/50/200; IVF with 16/64 lists and total canonical budgets 128/256/512/1213, with cold and admissible C-budget warm variants. Three 80-request replays produce 10,560 measured searches; ordinary warmup adds 2,112 and candidate filling 1,632, totaling 14,304 searches. Candidate writes are recorded separately.

The compact bank stores old-query float64 arrays and ID/version int64 arrays. It retains the same full-bank read/copy policy; it is not given an oracle for which payload to fetch. All six layout pairs have identical filled seeds and replay results. The small two-dimensional fixture does not always become smaller in binary form; the earlier unconditional assertion was corrected and recorded.

The C50 layout change reduces foreground time about 46.7%, matching time 96.9% and payload 58.9% relative to JSON. Payload excludes Python objects, allocator overhead and transient peak copies. The pooled compact-versus-ANN difference of about 3.9% is not repeatable: compact is slower in the first two rounds and ANN is noisier in the third. It is not an architectural speedup claim.

IVF cold priority uses q·center. The warm route first validates and rescores seeds, then uses observed current seed scores in partition priority. It skips already scored IDs when scanning postings. The total canonical budget includes seeds. Posting enumeration and score cursors are distinct and resumable; there is no geometric pruning or calibrated early stopping in this part.

At IVF16/B256, 200 seed scores plus 56 new scores equal 256 and 2,097,152 logical vector bytes. The gain is 13.4375 percentage points in average overlap, not fewer scores. The minimum remains below the gate. IVF16 warm/B512 meets the research floor, but IVF64 cold/B512 already gives 100% with lower mean latency. Warm/B512 versus cold/B1213 would misleadingly show 57.8% fewer scores: cold/B512 dominates that comparator. The paired diagnostics retain, but do not claim, those weak-baseline comparisons.

All arms have the same ordinary forced-repeat hit rate, 123/240=51.25%, not a natural hit-rate estimate. Three-replay workflow time is about 1450.7 ms for ANN, 1703.7 ms for compact merge C50 and 2171.0 ms for JSON merge C50. IVF64 cold/B512 costs about 1489.7 ms versus warm C50/B512 at 1884.3 ms, excluding separately shared builds. Filling and maintenance remain material.

Shared IVF construction takes roughly 107.5/113.2 ms for 16/64 lists; metadata payloads are 150480/543696 bytes. List sizes range 35–112 and 3–56. ANN indexes remain resident for warmup/fill, so process memory is not pure-IVF minimum memory. One separate startup probe reports executor import .218 s, sklearn import 1.001 s and child wall time 1.382 s with OS cache uncleared; it is not retroactively part of replay timing or a cold-disk guarantee.

Ten fictitious mechanics checks pass. They cover layout equivalence, full-budget agreement, seed/frontier/score continuation, common cache source/commit actions, empty filters/banks, unsupported caps and snapshot binding. Raw request checks also validate budgets and sources. This is not process-fault, concurrency, numerical certification or formal semantic validation. I retain compact layout as shared engineering capability, keep seed paths optional and stop the parameter matrix. Stage 3.3 remains a separate proposed part.
