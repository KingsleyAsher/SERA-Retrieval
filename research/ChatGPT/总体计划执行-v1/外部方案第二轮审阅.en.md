# Second proposal review: actionable mechanisms and unresolved guarantees

[English](外部方案第二轮审阅.en.md) | [简体中文](外部方案第二轮审阅.md)

This is a historical review dated 2026-10-28. I reviewed DeepSeek follow-up 2 (280 lines) and the then-current WorkBuddy residual proposal (507 lines). I accepted only conditional mechanisms; no new database experiment or model training was performed, and stage 2 had not started.

DeepSeek's external completion can rescore legal cached IDs, inspect a bounded neighborhood and merge candidates. It is not a true USearch warm start unless it changes the backend entry/frontier/visited state. Neighborhood construction, validation, calibration and fallback remain paid work.

The earlier 24/32 observation means the old candidate set already contained the complete new exact top-10 for those particular cases. Under one snapshot, score and tie order, correct rescoring that preserves the seed top-K cannot simultaneously miss a top-K member outside that set. Failure examples need a non-covering set or an additional execution fault. Similarly, a result that genuinely misses top-K must have an undiscovered item that outranks its current Kth boundary.

I separate recall target Rt, failure event Y, allowed failure probability δ and direct-return fraction. A model score alone is no probability guarantee. If the specific conditional event of missing any exact top-K item is bounded by δ, expected conditional recall is at least 1−δ; that is not per-query recall or semantic relevance. Calibration should use independent exact references, not ANN outputs assumed to be truth or only the fallback subset.

The executable specification must sort before selecting a Kth threshold, distinguish IDs from result objects, deduplicate by ID, and score neighbors against the current query. Candidate legality does not establish neighborhood freshness. A first version may bind one snapshot; cross-update reuse needs a separate change-log protocol. Unshared neighborhood storage scales as entries×C×M, not entries×K×M.

With direct-return fraction p, local overhead Tl, baseline global cost Tg, fallback merge cost Tm and amortized construction/maintenance/audit Ca, the simplified mean cost is `Tl+(1−p)(Tg+Tm)+Ca`. Net savings require `p*Tg>Tl+(1−p)*Tm+Ca` and independent quality acceptance. Correlated fallback cost requires conditional expectations. The old ~0.196 ms loaded ANN microbenchmark is not end-to-end cost.

WorkBuddy's exact reference must decode FP32 coordinates into integers before subtraction. Floating subtraction followed by scaling cannot recover lost low bits, as 1 and 2^-100 show. At common coordinate scale 2^149, let `A=(2^24−1)<<253`; the maximum squared-distance integer is `D*(2A)^2`. Magnitude widths are 566, 567 and 572 bits for D=1024, 1536 and 65536. A 576-bit container can fit those cases, but an unproved 128-bit typical-case shortcut cannot replace arbitrary precision.

OPQ's original formulation constrains `RᵀR=I`; implementation rounding is a separate problem. If an exact transform has certified `||RᵀR−I||₂≤ε<1`, a transformed squared-distance lower bound maps back as `LB/(1+ε)` and an upper bound as `UB/(1−ε)`. Multiplying UB by 1+ε is unsafe: R=.99 gives `.9801*1.0199=.99960399<1`. Floating transform/reconstruction error still needs additional treatment.

Committed publication is authoritative even if its response was lost; operation IDs and request digests support idempotent retries. Known action costs must be admitted before execution. P90 prediction is not an automatic 10% underestimation guarantee. I retain identity residual mathematics and the exact-integer reference, defer nonidentity certification, and keep the original order of testing block bounds before adding residual layers. This review produced corrected conditions, not a new speedup or novelty result.
