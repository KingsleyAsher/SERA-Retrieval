# Third proposal review: converging references, incomplete reuse policy

[English](外部方案第三轮审阅.en.md) | [简体中文](外部方案第三轮审阅.md)

On 2026-10-28 I reviewed two frozen inputs totaling 39,802 bytes and 681 lines: DeepSeek follow-up 3 and WorkBuddy's revised residual specification. Identical filenames did not imply identical content; hashes distinguish revisions. This part remained a document/arithmetic review, with no stage-2 implementation or performance run.

DeepSeek withdrew the incompatible complete-coverage/missing-top-K example, called its path external completion, separated Rt/Y/δ/delegation rate, sorted thresholds and fixed C-based storage accounting. The first version now accepts only one snapshot. WorkBuddy adopted bit-pattern decoding, corrected width reasoning and OPQ's theoretical orthogonality, and deferred nonidentity certification.

Four reuse issues remain. First, an exact query signature only supports repetitions; it cannot explain rewrite reuse. Ordinary exact-request caching is a strong baseline, and any repeated-query neighborhood enhancement must offer the baseline the same one-time enhancement opportunity. A compatibility key binds model, preprocessing, score, scope, snapshot and K; it is not a similarity match, and a hash collision is not a semantic hit.

Second, the return gate must allow useful new neighbors into the result. For K=2, seeds at distances 2 and 3 plus a neighbor at 1 produce the legitimate local result 1 and 2. Requiring every returned ID to be an original seed rejects the improvement. Requiring only that returned items were scored establishes execution completion, not global completeness. Expanding C=200 seeds with M=32 can inspect up to 6,400 edges in a 1,213-chunk corpus; expansion and unique scoring need explicit limits.

Third, empirical calibration needs finite-sample and selection control. For a fixed policy and n genuinely independent accepted cases with zero failures, the one-sided 95% exact binomial upper bound is `1−0.05^(1/n)`. It is about 11.73% at n=24; at least 59 such cases are needed below 5%. Family variants are not independent new evidence, and threshold selection on the same calibration set creates bias. A representative accepted group can support a conditional statement without requiring every rejected risk group to be labeled. At K=10, Rt=.95 happens to require all ten; that equivalence does not generalize to arbitrary K/Rt.

Fourth, ablations need causal discipline. A neighborhood arm beating its no-neighborhood counterpart but losing to a stronger baseline does not prove the gain came only from seeds. Policies may need separate calibration. Different difficulty in delegated/direct groups is not itself failure. AUROC near .5 does not exclude a useful low-risk constant policy. I prefer rules and constants before model training, and P50/P95 plus raw distributions before P99 claims.

The exact FP32 reference uses common distance units 2^-298 and arbitrary-precision integers. Future reduced-scale arithmetic must define h from the raw exponent consistently, ignore zero when finding exponent ranges and handle the all-zero case. No 128-bit path is admitted yet.

Identity residual mathematics is valid, but a final upward rounding or one-ulp addition cannot repair an underestimated earlier norm. A conservative chain needs an upper residual r_U, lower reconstruction distance a_L and downward evaluation of `max(sqrt_down(a_L)−r_U,0)^2`, compared strictly with a supported threshold upper bound. The independent verifier remains necessary.

SQLite COMMIT durability depends on WAL/synchronous configuration and device semantics; it does not sync external segments automatically. Persist immutable objects first, then atomically commit publication and operation-ID/digest/result state. For asynchronous work, admit `consumed+reserved+next≤budget` atomically. Resumable exhaustion yields Pending rather than an unconditional rejection. No bounded wall-clock overshoot is promised without a cancellation model.

Aker and FreshCache figures remain author reports. The cited DARTH HNSW 6.8× / IVF 13.6× pair was not located in that review and is unverified rather than declared fabricated. QVCache establishes related query-level caching work, not SERA's advantage. My outcome was a narrower executable reference and explicit remaining conditions; semantic labels still required review and stage 2 remained unopened at this date.
