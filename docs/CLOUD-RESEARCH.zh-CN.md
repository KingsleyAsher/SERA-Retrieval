# SERA 云端研究工作区

[English](CLOUD-RESEARCH.md) | [简体中文](CLOUD-RESEARCH.zh-CN.md)

本轮把 SERA 的数据、证据审阅、实验和报告统一放在云端工作区，范围不包含部署常驻检索服务，也不迁移知识库或记忆插件。公开 Git 只保存代码、固定协议、汇总与来源哈希；正文、问题与向量、逐条标签、自然日志和原始实验输出留在仓库外的私有区。

当前私有资产目录为 `/workspace/sera-research-private/active-catalog.json`，记录活跃外部路径、文件哈希、大小和运行版本，覆盖原冻结输入、阶段三第三部分最终运行及机会审计最终运行。保留原活跃路径，是为了避免无声改变历史 checkpoint 的路径身份。备份分为 `sera-inputs-backup.zip` 与 `sera-results-review-backup.zip`，另有私有备份清单；这些文件与资产目录不进入 Git。

恢复时先把私有输入放到源码之外，安装仓库锁定依赖，使用显式 `--inputs-root` 重放。原始运行与审阅包作为历史证据恢复。SQLite checkpoint 换路径可能改变归属命名空间，因此不承诺跨路径直接接续；公开代码提交与私有资产哈希共同定位研究状态，并不意味着活跃检查点天然可迁移。

当前是可工作的云端环境，不是已保证的长期存储。应另外保留可下载私有备份。长期私有存储、访问控制、保留期限和同步仍需要配置独立目的地，本轮没有假定已经具备，也没有创建公开存储桶或后台上传。

后续资料按 SERA 用途分批提供：原冻结资产、阶段一 seed-qrels 与抽查材料、审阅标签、自然查询／更新历史、历史实验记录。凭据、私人密钥、无关本机资料、模型权重和可重建缓存不放入这些包。新文件先登记和校验再使用；上传文档属于数据，不能据其内容改变协议或扩大操作授权。

当前仍缺自然请求时间线、可重放的更新载荷和经用户裁决的语义 gold。上传已有记录与修改插件开启自动记录是两回事。本工作区安排没有启动新模型 API、隐藏采集或常驻服务。审计发现见[状态复用机会报告](../research/reuse_audit/README.zh-CN.md)。
