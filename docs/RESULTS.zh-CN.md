# 当前实验能说明什么

[English](RESULTS.md) | [简体中文](RESULTS.zh-CN.md)

我将工程改进与架构优势分别判断。现有证据确认了布局改进，也出现了局部机制信号；相对强检索基线的稳定综合优势仍未证实。

阶段三第一部分测量了 4,800 个请求。只用缓存种子会漏检，候选合并保留了完整 ANN 搜索又增加开销，两者都没有显示净优势。

第二部分包含 44 个配置、10,560 个测量请求；计入普通预热和候选填充，共执行 14,304 次检索。工作负载只有 16 个开发问题族、48 个不同文本和 32 个改写，重复回放不增加独立样本数量。

| 对照 | 观察结果 | 我对结果的判断 |
|---|---|---|
| JSON 合并 C50 → 紧凑合并 C50 | 7.517 → 4.006 ms；匹配开销约降低 96.9%，载荷约减少 58.9% | 返回结果一致，布局收益可重复 |
| 紧凑合并 C50 与 ANN50 | 汇总均值分别约 4.006、4.168 ms | 各轮方向不一致，填充后完整工作流更贵，不能宣称稳定加速 |
| IVF16、总评分预算 256 | 冷启动平均重合 84.375%；C200 热启动 97.8125%，最差 80% | 同预算平均覆盖改善，但耗时增加，长尾漏检仍存在 |
| IVF64、预算 512 | 冷启动已达到 100% 向量前十重合 | 不能拿热启动 512 对比冷启动 1213 宣称热启动新增节省 |

256 次评分包含 200 次种子评分和 56 次新增评分，没有免费增加候选。载荷统计不含 Python 对象、瞬时副本和 RSS。前十重合比较的是规范向量结果集合，不是语义准确率。

语义标签仍未核实；未缓存的嵌入网络延迟、物理冷读取、RSS、并发更新、完整崩溃恢复及大规模效果尚未验证。阶段二历史耗时属于当时的修前代码，不能直接归到修后版本。本项目目前不据此宣称生产保证、原创性确认或代际提升。
