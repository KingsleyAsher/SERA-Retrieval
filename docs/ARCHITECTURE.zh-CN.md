# 架构与执行契约

[English](ARCHITECTURE.md) | [简体中文](ARCHITECTURE.zh-CN.md)

我把检索表示为一系列有成本、可记录、可接续的动作。一次请求固定查询向量、过滤范围、快照、评分契约、质量目标和资源额度；执行状态保存候选与分数、后端进度、版本依赖、已完成动作以及累计消耗。

当前参考实现采用 Python 与 SQLite，包含完整 float64 内积评分、USearch 取候选后按规范契约重排，以及中文词法／向量混合检索。阶段三第二部分加入可控 IVF：合法旧候选先按当前查询重新评分，再影响分区访问顺序。种子读取与评分占用总预算，和新增扫描采用同一计费规则。

资源账分别记录模型／网络、本地计算、逻辑读取、缓存占用、初始化、维护、来源访问、提交及失败回退。接续和回退不会自动获得新额度。已知动作成本在发起前原子准入；原生 ANN 调用内部不支持的硬上限明确拒绝，不能把事后计数写成已执行的硬限制。

结果接口预留近似、概率保证、严格认证、待完成和拒绝等状态；预留类型不代表对应保证已经实现。当前日常路径不发严格证书，也不直接继承其他论文的概率保证。来源检查针对快照中的物化正文，不等于独立核验原始文件的真实性。

独立的[阶段三第三部分执行器](../research/stage33/README.zh-CN.md)已经分开访问顺序与未完成区域覆盖：打开 posting 不等于完成分区，活动尾部和已枚举未评分项保留在接续状态，真正完成评分才消除对应工作。公开机制检查已通过；128 个冻结输入离线情形已运行且未显示剪枝潜力，未用界执行在线停止。

日常归一化 float64 内积与未来存储 FP32 坐标的实数平方 L2 认证契约保持独立。普通浮点几何诊断不能在缺少数值证明时充当严格证书。
