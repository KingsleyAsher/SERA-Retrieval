# Citing the project and its evidence

[English](CITATION.md) | [简体中文](CITATION.zh-CN.md)

I publish machine-readable citation metadata in `CITATION.cff`. The project is SERA: Stateful Execution for Retrieval Architectures, maintained under the KingsleyAsher account. The repository is https://github.com/KingsleyAsher/SERA-Retrieval. The initial public archive date is 2026-10-29; a repository date is not a claim of peer-reviewed publication or a formal release study.

For a result, cite the specific commit and the relevant stage report as well as the project. Identify its snapshot, code hash, workload and quality metric. Label private-input results accordingly. In particular, compact-versus-JSON improvement is not an ANN advantage, and exact-vector overlap is not semantic accuracy.

When referring to an external proposal or paper, cite its actual source separately. My integration decisions, model-assisted proposals, executable checks and measured experiments are different kinds of evidence. A future DOI may identify a frozen milestone; no DOI has been assigned here.
